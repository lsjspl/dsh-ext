## 实现计划：归档 → 回收站 → 删除

### 背景结论（已查实）
宿主 `@deepseek-ai`（dsh-workspace / dsh-client-runtime / host-apiproxy / storage-domain）**没有**反归档/还原的内存接口：唯一方法是 `archiveSession(sessionId)`，实现是 `archivedSessionIds: [...state.archivedSessionIds, sessionId]`（只能追加，`lib/index.js:422`），全 node_modules 无 `unarchive/restore/setArchived`。RPC 路由表也只有 `workspace.archiveSession`，无反归档路由。

`ctx.storageDomain.open(workspaceDomainSpec)` 走后门写 global **不可行**：DomainFacility 强制单开（`already-open`），且即使拿到已开句柄 `global.set()` 也只写盘、不更新 `WorkspaceRegistry` 私有 `this.state`（只在 `Service.init` 时 `global.get()` 一次）。所以内存副本始终是旧的。

**结论**：还原只能直接改盘上 `~/.dsh/storages/workspace.json` 的 `global.archivedSessionIds`，需要刷新页面才生效。这正好贴合用户要求的"把归档标志改回去 + 提醒刷新"。

### 一、后端 `src/features/session-admin.ts` + `src/paths.ts`
- `paths.ts`：新增 `storages: dshHomePath('storages')`，用于定位 `workspace.json`。
- 回收站语义从"插件物理移动的 trash 目录"改为"宿主已归档会话"：
  - 移除 `TrashManifest`、`readTrash`、`assertTrashId`、`TITLE_SCAN_BYTES/TITLE_BUDGET`（仅 trash 部分）、`trash` 目录相关代码。
  - `/sessions/delete` 移除（归档不再物理移动文件，改由客户端调宿主 `archiveSession`）。
  - `/sessions/restore` 改为：读 `workspace.json` → 从 `global.archivedSessionIds` 移除该 id → 读-改-写原子写回（`writeFileAtomic`），保留 `unit`/`global.initialized`/`workspaceIds`/`tables` 等其它字段。返回 `{ restored, reloadRequired: true }`。
  - `/sessions/purge` 改为真删除：用 `sessionPersistence.locate()` 定位归档会话文件并 `rm`，同时从 `global.archivedSessionIds` 移除该 id；`{all:true}` 清空全部归档会话。
  - `/sessions/archived`（可选）：专供回收站弹窗列表，用 `locate()` 为每个归档 id 生成行。

### 二、客户端回收站弹窗 `src/client/TrashModal.tsx`
- 数据源改为已归档会话（`/sessions/archived` 或 `/sessions` 的 `archived` 字段）。
- 还原按钮 → `/sessions/restore`，成功提示"还原成功，刷新页面后才会显示"（写入 `locales.ts`）。
- 永久删除 / 清空 → `/sessions/purge`。
- 标题、空态文案从 `trash` 语义改为 `archived` 语义。

### 三、撤销/编辑后归档原会话（不再物理删除）
- `src/client/TurnChangesCard.tsx`：`trashSession` 改为调宿主 `ctx.workspaces.archiveSession(props.sessionId)`；`props.workspaces` 类型扩宽为 `{ connectWorkspace; archiveSession }`。撤销成功 fork 后归档旧会话。
- `src/client/UserEditBubble.tsx`：编辑重发后 fork 同样归档原会话。

### 四、移除设置页会话记录页
- 删除 Settings 的会话记录 tab（`SessionsPanel` 及其在设置页挂载），保留左侧栏 `sidebar.footer.action` 回收站入口（已完成）。

### 五、配置与文案
- `src/config.ts`：移除仅用于旧物理 trash 语义的 `trashEnabled`（归档始终进回收站，永久删除为显式操作）。
- `src/client/locales.ts`：新增 `sessions.restoreRefreshNeeded`（还原后需刷新），`trash*` 文案改为 `archived*` 语义（中英）。

### 风险与断言
- 还原依赖宿主下次启动重新读盘（`Service.init` 时 `global.get()`），**整页刷新（重新加载）**生效；仅点侧栏刷新不会重新读盘。提示文案用"刷新页面"。
- 还原只改盘而不更新宿主内存副本，若还原后、刷新前宿主又做归档/建仓/删除，会把旧内存状态整组写回（成 lost-update）。规避：还原成功后明确提示"先刷新页面再执行其它操作"。
